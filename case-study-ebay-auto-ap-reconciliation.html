Accounts payable automation case study

eBay Auto AP Reconciliation.

A custom ERP module that takes a large weekly eBay remittance file, matches it to the penny, flags what doesn’t match, and posts hundreds of balanced entries with one click.

The challenge

Hundreds of payments, every week, none of them tidy.

Every week eBay sends a remittance file covering 300 to 500 payment references. Each one has to be matched to the right invoice, to the penny, and posted to the right general ledger accounts. Anything that doesn’t match — a short payment, a missing credit, an invoice that was never created — has to be researched and fixed by hand before the books will balance.

Done manually, a single file could take half a day or more, and every manual match was another chance for error.

“The system does the matching. The user makes the decisions.”

The solution

Upload the file. Review the exceptions. Click Update.

We built a custom module inside the ERP that imports the eBay remittance file and does the reconciliation work. Exact matches are confirmed automatically. Mismatches are surfaced with a confidence score for the most likely correct match, and the user approves it or changes it on the fly.

Missing credits and invoices are created automatically so every posting balances to the penny. One click on Update posts the whole file.

What the user sees

  • Exact matches — one to one, to the penny and invoice number
  • Mismatches — each with a confidence score
  • Approve or change any suggested match on the fly
  • Missing credits and invoices — created automatically
  • Balanced postings to the correct GL accounts
Import → Match → Review Mismatches → Auto-Create Missing → Update. A human-in-the-loop design: the module handles the volume, and the user only spends time on the exceptions that need judgment.

How it works

Five steps, one file.

01

Import the eBay file

The user uploads the weekly remittance file, 300 to 500 payment references at a time.

02

Exact matches reported

Every payment that matches an invoice one to one, to the penny and invoice number, is reported back to the user.

03

Mismatches scored

Each mismatch is reported with a confidence score for the match the module believes is correct. The user approves it or changes it on the fly.

04

Missing items auto-created

Missing credits and invoices are created automatically so the posting balances to the penny.

05

One click to post

The user clicks Update. Hundreds of postings, new invoices and credits are posted and balanced at the end.

Built through iteration

The edge cases are the real work.

Reconciling a clean payment is easy. The difficulty is everything else. This module took many iterations to account for the edge cases in real remittance data and to decide how each one should be handled, so that the output still balances to the penny.

Every posting is connected to the correct GL accounts, so the accounting is right the moment the user clicks Update, not after a cleanup pass.

“Automation handles the volume. People handle the judgment calls.”
